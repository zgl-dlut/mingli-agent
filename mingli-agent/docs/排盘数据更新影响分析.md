## 一、更新内容概述

### 1.1 新增字段

| 字段名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| `空亡` | Array | 日柱旬空地支 | `["戌", "亥"]` |
| `长生十二宫` | Object | 四柱长生状态 | `{"年": "冠带", "月": "冠带", "日": "长生", "时": "沐浴"}` |
| `神煞` | Object | 四柱神煞列表 | `{"年": ["华盖", "国印", "空亡"], ...}` |
| `天干五合` | Array | 天干合化关系 | `["甲己合化土"]` |

### 1.2 更新字段

| 字段名 | 旧值 | 新值 | 变化原因 |
|--------|------|------|----------|
| `旺衰结论` | 身弱 | 身旺 | 新增"得局"维度，计算申酉戌三会金局 |
| `旺衰详情` | 缺少得局分析 | 包含得局分析 | 新增合局/刑冲计算 |

### 1.3 计算逻辑变更

**旧逻辑**（3个维度）:
- 得令（月令生扶）
- 得地（地支藏干根气）
- 得势（天干生扶）

**新逻辑**（4个维度）:
- 得令（月令生扶）
- 得地（长生十二宫根气）
- 得势（天干生扶）
- **得局（地支合局/刑冲）** ← 新增

## 三、影响范围分析

### 3.1 对已生成报告的影响

**影响级别**: ⚠️ 无影响

- 已生成的首次报告和追问报告存储在 `chat_messages` 表
- 报告内容（`content`字段）是生成时的快照，不会随排盘数据更新而变化
- 用户查看历史报告时，看到的仍是生成时的内容

**验证方法**:
```sql
-- 查看已生成的报告
SELECT id, session_id, role, LEFT(content, 100) as preview, created_at
FROM chat_messages
WHERE role = 'assistant'
ORDER BY created_at DESC;
```

### 3.2 对新追问报告的影响

**影响级别**: ✅ 正面影响

- 新的追问会使用更新后的排盘数据
- LLM会基于"身旺"结论生成更准确的分析
- 新增的神煞、长生十二宫等信息会传递给LLM，丰富报告内容

**示例场景**:
- 用户问："我适合从事什么行业？"
- 旧逻辑（身弱）：建议从事金水行业（印比）
- 新逻辑（身旺）：建议从事木火行业（食伤财），更符合实际

### 3.3 对前端展示的影响

**影响级别**: ⚠️ 需要检查
