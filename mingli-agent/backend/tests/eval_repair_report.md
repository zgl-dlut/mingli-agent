**测试数据**: 5 条真实追问报告（session_id=21）

---

## 问题描述

原标题检查器使用简单正则 `[\u4e00-\u9fa5]{2,6}` 提取关键词，导致：
1. 无法识别含数字的关键词（如"27年"、"10月"）
2. 跨停用词匹配产生无意义片段（如"年的"、"月或者"、"月底是有一大"）
3. 大量误报：12 次"标题未贴合用户原话"违规，实际标题质量良好

---

## 剩余违规分析

修复后剩余 17 次违规均为**真实问题**：

### 1. 标题未贴合 (3 次)
- "拿到这笔钱的关键前置动作" - 字符重叠仅 1 个
- "入职新公司的完整路径与时间节点" - 字符重叠仅 1 个
- "新领导是否已在公司及资历深浅" - 字符重叠仅 1 个

**建议**: 这些标题虽然回答了问题的某个方面，但与原问题关键词关联较弱，可接受为合理违规。

### 2. 术语无解释 (8 次)
- "七杀"、"正官"、"用神"、"流月" 等术语在 narrative 中出现但未紧跟括号解释

**建议**: 这是 LLM 生成时的常见问题，需要在 prompt 中强化术语解释要求。

### 3. narrative 过长 (1 次)
- 报告 #3 有一条 narrative 122 字（上限 120）

**建议**: 轻微超标，可接受或调整上限至 130 字。

### 4. 命盘使用违规 (4 次，仅报告 #5)
- 用神不一致、编造命盘未提供的信息等

**建议**: 这是最严重的问题，需要优化 LLM 的命盘数据引用逻辑。

## 结论

1. **关键词提取优化显著减少误报**：标题误报从 12 次降至 3 次（-75%）
2. **剩余违规均为真实问题**：术语无解释、命盘使用违规等需要 LLM 侧优化
3. **编造检测有效**：成功识别出软性评分高但内容编造的report
4. **建议后续优化**:
   - 在 LLM prompt 中强化术语解释要求
   - 优化命盘数据引用逻辑，避免编造
   - 考虑将 narrative 上限从 120 字调整至 130 字
