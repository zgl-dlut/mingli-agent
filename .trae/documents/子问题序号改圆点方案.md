# 子问题下 blocks 序号改为实心圆点

## 背景
用户反馈子问题下的二级段落（blocks）序号太生硬。当前序号来源：
- 前端 `FollowupReportView.tsx` 的 `SubtopicView` 在 keywordCount >= 2 时自动给每个 keyword block 加数字序号（1. 2.）
- `BlockView` 渲染 `{subSeq}. {keyword}`

之前我过度修改了：完全移除序号 + 加防御性去除 keyword 开头数字 + prompt 禁止序号。用户只要把数字序号改成实心圆点（•）。

## 目标
- blocks 每个前面显示实心圆点（•），不再用数字序号
- 回退序号相关的过度修改（防御性去除、prompt 禁止序号）
- 保留 CSS 间距和 prompt 术语/keyword 规则（针对用户其他反馈，不回退）

## 改动

### 1. 回退 BlockView 防御性去除
文件：`frontend/src/components/FollowupReportView.tsx` L146-153

移除 `cleanKeyword` 防御性去除逻辑，恢复直接用 `data.keyword`：
```tsx
function BlockView({ data }: { data: Block }) {
  if (data.type === 'keyword') {
    return (
      <>
        <p>
          <span className="block-bullet">•</span> <strong>{data.keyword}</strong>{data.narrative && <>：{renderBold(data.narrative)}</>}
        </p>
        ...
```

### 2. 回退 prompt 禁止序号规则
文件：`backend/app/services/followup_structured.py` L85

移除"keyword开头禁止加任何数字或中文序号"这段，恢复为：
```
- keyword字段绝对禁止添加**号或任何Markdown符号（前端组件自动加粗）；keyword必须是叙事化概括（如"被动换组反而是好事""9月返岗坑位变动""签字拿赔偿金时机"），禁止使用"补充提示""补充说明""其他提示""额外建议""现实剧本预测"这类空洞无信息或过于宽泛的词，必须根据本段narrative内容提炼出具体现实结论
```

### 3. CSS 圆点样式
文件：`frontend/src/index.css`

新增 `.block-bullet` 样式（实心圆点，颜色与正文一致）：
```css
.followup-report .block-bullet {
  color: var(--text);
  margin-right: 0.25rem;
}
```

## 不改动的部分
- `SubtopicView`：保留当前（不加数字序号，直接渲染 blocks）
- prompt 术语黑名单、keyword 叙事化规则、CSS 间距（0.5rem）：保留，针对用户其他反馈
