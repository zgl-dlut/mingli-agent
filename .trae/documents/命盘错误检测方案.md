# 命盘错误检测方案

## Summary

写一个**只读检测脚本**，遍历 persons 表全部 47 个 person，用各 person 的出生信息（birth_date/birth_time/birth_lat/birth_lng/gender/birth_location）现场重算命盘，与落库的 `bazi_data_json` 比对关键字段，量化"有多少命盘是错的"+ 差异明细。**只检测不改数据**，根据错误规模再决定后续处理（全量重算/加版本号/懒迁移）。

## Current State Analysis（现状）

- **persons 表字段全**：name/gender/birth_date/birth_time/birth_location/**birth_lat/birth_lng**/calendar_type/province/city/bazi_data_json/created_at。47 个 person 全部有命盘和经纬度。
- **命盘存储**：`create_person` 时调 [orchestrator.py:207](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/skills/orchestrator.py#L207) `generate_full_analysis` 生成，存 `person.bazi_data_json` + `session.bazi_data_json`。
- **追问读取命盘**：[chat.py:244-296](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/api/chat.py#L244) 优先用 `person.bazi_data_json`，**只在缺流月十神字段(shishen_tian)时才重算回写**。若落库命盘本身错（非缺字段），追问一直用错的。
- **命盘无版本标记**：顶层 30 字段无 `chart_version`，无法靠字段区分"旧算法生成的命盘"。
- **算法迭代过多次**（project_memory 记录：早子时/合局/旺衰/德秀贵人/羊刃/国印贵人等 bug 都修过），8 月 13 个 person 可能用旧算法、9 月 34 个用新算法，但无法精确切分。
- **经纬度用户确认可信**，错命盘主要来自算法迭代，重算可修。

## Proposed Changes

### 1. 检测脚本 `/tmp/detect_bad_chart.py`（只读，不回写）

逻辑：
1. 查询 persons 表全部记录（id/birth_date/birth_time/birth_lat/birth_lng/gender/birth_location/bazi_data_json/created_at）
2. 对每个 person，用其自身的出生信息调 `generate_full_analysis` 现场重算
3. 落库命盘 vs 重算命盘，比对以下**不随时间漂移的关键字段**：
   - `四柱`（最核心）
   - `日主`
   - `用神` / `喜神` / `忌神`
   - `大运列表`（比对 ganzhi 序列）
   - `当前大运`（2026 年不变，可比）
   - `起运年龄`
   - `旺衰结论`
4. 任一字段不一致 → 该命盘判"错"，记录 person_id + 差异字段 + 落库值 vs 重算值
5. 输出汇总：
   - 总 person 数 / 错命盘数 / 错误率
   - 按 created_at 月份分组（看是否集中在旧算法期）
   - 每个错命盘的 person_id、差异字段清单、落库值 vs 重算值示例（前 2-3 个详列）

### 2. 执行脚本出报告

在生产容器跑（`docker exec -w /app -e PYTHONPATH=/app mingli-backend python /tmp/detect_bad_chart.py`），脚本结束自动清理。排盘是本地算法（不调 LLM），47 个重算秒级完成。

### 3. 后续处理（不在本次范围，等检测结果定）

根据错误规模选：
- 错得多（如 >30%）→ 全量重算回写 + 给 `generate_full_analysis` 输出加 `chart_version`，追问入口校验版本旧则重算（根治）
- 错得少 → 懒迁移，追问时校验版本/比对关键字段不一致才重算
- 几乎没错 → 仅加 `chart_version` 防未来

## Assumptions & Decisions

- **经纬度可信**（用户确认）：重算用相同 birth_lat/birth_lng，差异判定为算法迭代导致，非坐标问题。
- **比对字段选"不随时间漂移"的**：四柱/日主/用神/大运列表/起运年龄/旺衰结论是命盘固有属性，不随当前年份变；当前大运 2026 年内稳定可比。重点流年范围可能因代码改过略变，不作为硬判据，仅记录。
- **只读不改**：脚本不回写 person.bazi_data_json，避免检测过程中污染数据；确认要修才单独执行修复脚本。
- **差异即"错"**：落库与重算不一致，认定落库是旧算法结果、重算是当前算法结果，落库为"错"（因为当前算法已修已知 bug）。

## Verification

1. 脚本跑完输出"错命盘数/总数"汇总。
2. 抽 1-2 个错命盘人工核对：确认差异字段确实来自算法迭代（如旧版无合局计算导致旺衰结论不同），而非脚本比对 bug。
3. 抽 1 个"对"命盘确认无差异（脚本没误报）。
4. 把错误规模和分布报给用户，由用户定后续处理方案。
