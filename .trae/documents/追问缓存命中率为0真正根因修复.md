# 追问缓存命中率为0 — 真正根因与修复方案

## Summary

追问缓存命中率始终为0。之前的修复（提取逻辑、显式缓存标记）都无效。**真正根因：`build_cache_control_messages` 把整个 system_prompt（含动态命盘数据）作为一个 text block 标记缓存，由于动态部分每次追问都不同，整个 text block 每次都不同，缓存永远命不中。**

## Proposed Changes

### 改动：把 system_prompt 拆成固定+动态两个 text block，只给固定部分加 cache_control

**文件**：`backend/app/services/ai_service.py`

**函数**：`build_cache_control_messages`（line 40-62）

**做什么**：修改函数，自动检测 `# 本次会话信息` 分隔符，把 system_prompt 拆成两个 text block：
- 固定部分（分隔符之前）：加 `cache_control: {"type": "ephemeral"}` 标记
- 动态部分（分隔符及之后）：不加标记

```python
def build_cache_control_messages(system_prompt: str, user_messages: list) -> list:
    # 在 "# 本次会话信息" 处拆分 system_prompt
    SPLIT_MARKER = "# 本次会话信息"
    split_idx = system_prompt.find(SPLIT_MARKER)

    if split_idx > 0:
        fixed_part = system_prompt[:split_idx].rstrip()
        dynamic_part = system_prompt[split_idx:]
        content_blocks = [
            {
                "type": "text",
                "text": fixed_part,
                "cache_control": {"type": "ephemeral"},
            },
            {
                "type": "text",
                "text": dynamic_part,
            },
        ]
    else:
        # 兜底：无分隔符时整体标记（不如拆分好，但比不标记强）
        content_blocks = [
            {
                "type": "text",
                "text": system_prompt,
                "cache_control": {"type": "ephemeral"},
            },
        ]

    return [{"role": "system", "content": content_blocks}] + user_messages
```

**为什么**：
- 固定部分约 8000+ tokens，每次追问完全相同 → 标记后 5 分钟内可命中
- 动态部分每次不同 → 不标记，不缓存
- 拆分后缓存命中部分约占 prompt 的 60-70%，节省显著

**对首次报告的影响**：首次报告的 system_prompt 也有类似结构（prompt_builder.py），但首次报告每次都是新人物、新命盘，缓存命中价值不大。本次只改 `build_cache_control_messages` 函数，首次报告如果也调用此函数会自动受益（如果 prompt 中有 `# 本次会话信息` 标记的话）。如果没有此标记则走兜底分支，不影响原有行为。

### 不需要改动的部分
- `build_structured_prompt` 函数：不需要改返回结构，通过分隔符自动拆分即可
- `followup_structured.py` 的 3 处调用：不需要改，仍传 `system_prompt` 字符串
- cached_tokens 提取逻辑：已修复（dict.get 兼容），不需要再改

## Assumptions & Decisions

1. **分隔符选择 `# 本次会话信息`**：这个标题在 followup_structured.py 的 prompt 中明确存在（line 427），是固定部分和动态部分的天然分界线。

2. **兜底设计**：如果 system_prompt 中没有 `# 本次会话信息`（如首次报告的 prompt），走兜底分支整体标记。虽然整体标记命中率低，但不会比当前行为更差。

3. **不修改 build_structured_prompt 返回结构**：避免改动调用方的接口签名，通过分隔符自动拆分最小化侵入。

4. **阿里云显式缓存限制**：单次请求最多 4 个 cache_control 标记，这里只用 1 个，满足限制。缓存最小 1024 tokens，固定部分 8000+ tokens 满足。
