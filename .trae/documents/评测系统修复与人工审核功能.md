# 评测系统修复与人工审核功能

## 问题清单与根因分析

### 问题 1：eval_003/004/006 三个负面用例未匹配（检测准确率 58.3%）

**eval_003（keyword含术语）**：
- 测试数据：keyword = "七杀当令"，包含术语 "七杀"
- 预期违规：["keyword含术语", "block数量异常"]
- narrative_checker.py 第 46-54 行会检测 keyword 含术语黑名单词
- run_eval.py 第 60 行调用 check_narrative
- **根因分析**：应该被检测到，需要运行实际测试确认

**eval_004（narrative过短）**：
- 测试数据：narrative = "今年运势不错。"（7 字）
- 当前阈值：5 字（已从 30 改为 5）
- **根因确认**：7 字 > 5 字阈值，不会触发违规
- **修复方案**：将 narrative 改为 ≤5 字，如"运势好。"（3 字）

**eval_006（summary关键词泛泛）**：
- 测试数据：summary keyword = "蛰伏期"
- regex: `^[蛰伏蹲守守业过渡调整观望伏期守业期过渡期观望期]+期?$`
- **根因分析**：应该匹配，需要运行实际测试确认

### 问题 2：前端详情页显示逻辑错误

**当前状态**：
- 详情页只显示"检测通过"或"检测失败"
- 判断逻辑：`actual_pass == expected_pass` → 显示"检测通过"
- 问题：eval_002 预期违规 ["子问题漏答", "block数量异常"]，实际违规 ["子问题漏答", "block数量异常", "narrative过短"]，两者都 failed → 显示"检测通过"
- 用户期望：即使都 failed，也要展示违规项的差异

### 问题 3：生产数据 100% 采样 + 人工审核

**当前状态**：
- chat.py 第 381-403 行和 643-675 行调用 `should_deep_eval` + `save_monitor_result`
- `save_monitor_result` 只在 `should_deep_eval` 返回 True 时保存记录
- 大部分正常报告不满足触发条件，所以没有 production_monitor 记录

**用户需求**：
1. 上线初期 100% 采样（所有报告都保存监控记录）
2. 评测页面可查看内容详情（格式与用户看到的一致）
3. 支持人工提交审核意见
4. 审核意见自动加入评测集或新增评测条件

## 修改方案

### 修改 1：修复 eval_004 测试数据

**文件**：`backend/tests/eval_dataset.json`

将 eval_004 的 narrative 从 7 字改为 3 字（低于 5 字阈值）：
```json
{"type": "keyword", "keyword": "整体运势", "narrative": "运势好。"}
```

### 修改 2：运行实际测试确认 eval_003 和 eval_006

**步骤**：
1. 运行 `cd backend && source venv/bin/activate && python app/services/eval/run_eval.py`
2. 查看 eval_003 和 eval_006 的实际检测结果
3. 如果未检测到，检查对应的检查器逻辑

### 修改 3：前端详情页 - 违规项逐项对比展示

**文件**：`frontend/src/pages/EvalDetailPage.tsx`

修改违规项展示逻辑：
- 预期违规项 ∩ 实际违规项 → 标记为"✓ 已检测到"（绿色）
- 预期违规项 - 实际违规项 → 标记为"✗ 未检测到"（红色）
- 实际违规项 - 预期违规项 → 标记为"⚠ 额外检测到"（黄色）

修改"检测通过"判断逻辑：
- 当前：`actual_pass == expected_pass` → 显示"检测通过"
- 改为：只有当 `match == true` 且 `violations 完全匹配` 时才显示"检测通过"

### 修改 4：100% 采样 - 所有报告保存轻量监控记录

**文件**：`backend/app/api/chat.py`

修改第 381-403 行和 643-675 行，即使 `should_deep_eval` 返回 False 也保存记录：

```python
# 当前代码
need_eval, trigger_reason = should_deep_eval(...)
if need_eval:
    await save_monitor_result(...)

# 改为
need_eval, trigger_reason = should_deep_eval(...)
await save_monitor_result(
    report=report_data,
    user_question=question,
    user_id=user_id,
    session_id=session_id,
    trigger_reason=trigger_reason if need_eval else "no_trigger",
    is_first_report=False,
    generation_time=gen_time,
    chart_data=bazi_data,
)
```

**文件**：`backend/app/services/eval/production_monitor.py`

修改 `save_monitor_result` 函数（第 316-319 行），当 `trigger_reason == "no_trigger"` 时不执行 LLM 深度评测：

```python
# 当前代码
if eval_detail is None and chart_data:
    eval_detail = await run_deep_eval(...)

# 改为
if eval_detail is None and chart_data and trigger_reason != "no_trigger":
    eval_detail = await run_deep_eval(...)
```

### 修改 5：评测详情页 - 报告内容展示 + 人工审核

**文件**：`frontend/src/pages/EvalDetailPage.tsx`

新增功能：
1. **报告内容展示**：以用户看到的格式展示报告（subtopic 标题 + block 列表 + summary）
2. **人工审核表单**：
   - 审核意见文本框
   - 审核结果下拉框（通过/不通过/需改进）
   - 提交按钮
3. **自动加入评测集**：审核提交后，自动将报告加入 eval_dataset.json 或创建新的评测条件

**后端 API**：`backend/app/api/eval.py`

新增端点：
- `POST /api/eval/review` - 提交人工审核意见
- `POST /api/eval/add-to-dataset` - 将报告加入评测集
