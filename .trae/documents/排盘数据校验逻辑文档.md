# 排盘数据全链路校验逻辑文档

> 本文档描述排盘数据从计算到 LLM 输出全链路的校验机制，供后续维护人员参考。

---

## 一、数据流向总览

```
生辰输入 → 排盘计算 → 数据完整性校验 → 数据值正确性校验 → 持久化存储 → Prompt构建 → LLM生成 → 输出校验 → 生产监控
```

---

## 二、各环节校验详情

### 环节 2：数据完整性校验

**文件**: `backend/app/services/chart_validator.py`

**函数**: `validate_chart_data(analysis_data)`

**校验内容**: 8个关键字段非空

| 字段 | 类型 | 用途 |
|---|---|---|
| 日主 | str | 日主天干描述 |
| 四柱 | str | 四柱干支 |
| 用神 | str | 调候用神 |
| 忌神 | str | 忌神五行 |
| 旺衰结论 | str | 日主旺衰 |
| 格局 | str | 命局格局 |
| 当前大运 | str | 当前大运干支 |
| 重点流年 | list | 重点流年吉凶 |

**调用位置**: `backend/app/services/followup_structured.py` 第2568行

**失败处理**: 缺失字段标注 `MISSING_MARKER`（"（命盘数据缺失）"），LLM 收到后不编造该字段数据

---

### 环节 3：数据值正确性校验

**文件**: `backend/app/services/chart_validator.py`

**函数**: `validate_chart_data_with_values(analysis_data)`

**校验内容**:

| 校验项 | 规则 | 示例 |
|---|---|---|
| 四柱格式 | 必须"XX XX XX XX"，每个XX是天干地支组合 | "甲子 乙丑 丙寅 丁卯" |
| 四柱干支 | 每个干支必须在六十甲子中 | "甲子"合法，"甲丑"非法 |
| 日主格式 | 必须"X水/火/木/金/土"，X是天干 | "壬水"合法，"甲火"非法（甲应为木） |
| 用神/忌神 | 必须包含有效五行字符 | "金"、"金水"合法 |
| 当前大运 | 干支必须在六十甲子中 | "丁丑"合法 |
| 重点流年 | 每个流年干支必须在六十甲子中 | "丙午"合法 |

**调用位置**: `backend/app/api/chat.py`
- 追问报告流程：第284行
- 首次报告流程：第534行

**失败处理**: 记录告警日志，**不阻断流程**（避免误杀正常报告）

**日志示例**:
```
[chat] ✅ 排盘数据值校验通过
[chat] ⚠️ 排盘数据值校验失败: ["四柱格式错误: '甲子 乙丑 丙寅 丁卯 戊辰'"]
```

### 环节 4：持久化存储

**文件**: `backend/app/api/chat.py`

**存储策略**:
1. 优先从 `person.bazi_data_json` 读取
2. 若 person 没有，从 `session.bazi_data_json` 读取并同步回 person
3. 都没有则重新计算，同时写入 person 和 session

**校验日志**（第273-290行）:
```python
# 检查新增字段是否存在
has_shensha = '神煞' in bazi_data and bazi_data['神煞'] is not None
has_kongwang = '空亡' in bazi_data and bazi_data['空亡'] is not None
has_changsheng = '长生十二宫' in bazi_data and bazi_data['长生十二宫'] is not None
has_tiangan_he = '天干五合' in bazi_data and bazi_data['天干五合'] is not None
```

### 环节 5：Prompt 构建防护

**文件**: `backend/app/services/skill_prompts.py` / `backend/app/services/prompt_builder.py`

**防护机制**: 所有必需字段缺失时标注 `MISSING_MARKER`，LLM 收到后知道该字段无数据、不编造

**代码示例**:
```python
sizhu = analysis_data.get("四柱") or MISSING_MARKER
rizhu = analysis_data.get("日主") or MISSING_MARKER
```

### 环节 6：LLM 输出校验

**文件**: `backend/app/services/followup_structured.py`

**校验函数**（16个）:

| 函数名 | 校验内容 |
|---|---|
| `_detect_unfavored_year_actions` | 忌神年份不应有正面行动建议 |
| `_detect_favored_label_on_unfavored_year` | 忌神年份不应标注"有利"标签 |
| `_detect_favored_year_discouraged_actions` | 喜用年份不应有负面行动建议 |
| `_detect_yongshen_logic_conflict` | 用神/忌神逻辑一致性 |
| `_detect_forbidden_terms` | 禁止术语检测 |
| `_detect_ganzhi_time_notation` | 干支时间标注规范 |
| `_detect_synonym_contradiction` | 同义词矛盾检测 |
| `_detect_dimension_coverage` | 维度覆盖完整性 |
| `_detect_summary_duplication` | 摘要重复检测 |
| `_detect_timeline_inversion` | 时间线倒挂检测（离职≤offer≤入职） |
| `_detect_year_confusion` | 年份混淆检测（问27年只讲27年） |
| `_detect_past_month_suggestions` | 过去月份建议检测 |
| `_detect_month_without_liuyue_basis` | 流月建议无依据检测 |
| `_detect_liuyue_ganzhi_mismatch` | 流月干支与计算值不匹配 |
| `_detect_dayun_ganzhi_mismatch` | 大运干支与计算值不匹配 |
| `_detect_liunian_ganzhi_mismatch` | 流年干支与计算值不匹配 |
| `_detect_yongshen_wuxing_mismatch` | 用神五行与计算值不匹配 |
| `_detect_conclusion_without_bazi_basis` | 关键结论无排盘依据 |
| `_detect_missing_tool_calls` | 提到流月干支但未调用工具 |
| `_detect_llm_contradiction` | LLM 自相矛盾检测 |

**调用位置**: `followup_structured.py` 第2896-2912行

**失败处理**: 违规信息写入 `eval_results` 表，触发重试时附带修正提示

---

### 环节 7：生产监控

**文件**: `backend/app/services/eval/production_monitor.py`

**校验内容**:
- L1: 基础格式检查
- L2: 格式完成度（结构/叙事/命盘使用违规数）
- L3: 质量评估（违规数+拦截类型）

**调用位置**: `backend/app/api/chat.py` 第394-418行（追问）、第654-689行（首次）

## 三、校验层级关系

```
┌─────────────────────────────────────────────────────┐
│  环节1: 排盘算法正确性（离线测试，pytest）              │
│  → 确保 generate_full_analysis() 输出正确              │
├─────────────────────────────────────────────────────┤
│  环节2: 数据完整性（运行时，followup_structured.py）    │
│  → 确保8个关键字段非空                                  │
├─────────────────────────────────────────────────────┤
│  环节3: 数据值正确性（运行时，chat.py）                  │
│  → 确保四柱/日主/用神/大运/流年格式和范围正确             │
├─────────────────────────────────────────────────────┤
│  环节4: 持久化存储（运行时，chat.py）                    │
│  → 确保排盘数据正确写入数据库                            │
─────────────────────────────────────────────────────┤
│  环节5: Prompt构建防护（运行时，skill_prompts.py）       │
│  → 缺失字段标注MISSING_MARKER，防止LLM编造               │
├─────────────────────────────────────────────────────┤
│  环节6: LLM输出校验（运行时，followup_structured.py）    │
│  → 16个检测函数确保LLM输出与排盘数据一致                  │
├─────────────────────────────────────────────────────┤
│  环节7: 生产监控（运行时，production_monitor.py）        │
│  → L1/L2/L3三级评估，记录违规信息                        │
└─────────────────────────────────────────────────────┘
```

## 四、维护指南

### 新增测试用例

1. 在 `backend/tests/test_paipan_standard_cases.py` 的 `STANDARD_CASES` 列表中添加
2. 用例格式:
```python
{
    "name": "描述",
    "birth_date": "YYYY-MM-DD",
    "birth_time": "HH:MM",
    "longitude": 经度,
    "latitude": 纬度,
    "gender": "男/女",
    "location": "地点",
    "expected": {
        "四柱": "XX XX XX XX",
        "日主": "X五行",
        "旺衰结论": "身X",
        "用神": "五行",
        "忌神": "五行",
        "关键特征": [],
    }
}
```
3. 运行测试: `python -m pytest tests/test_paipan_standard_cases.py -v`

### 新增校验规则

1. **数据值校验**: 在 `chart_validator.py` 的 `validate_chart_data_with_values()` 中添加
2. **LLM输出校验**: 在 `followup_structured.py` 中添加 `_detect_xxx()` 函数，并在第2896-2912行调用
3. **Prompt防护**: 在 `skill_prompts.py` 的 `_build_context_vars()` 中添加缺失字段处理

### 排查校验失败

1. 查看日志: `docker logs mingli-backend --tail=100 | grep "排盘数据"`
2. 查看校验日志: `docker logs mingli-backend --tail=100 | grep "校验"`
3. 查看生产监控: 管理后台 → 生产监控页面
