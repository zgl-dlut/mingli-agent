# 每日运势与打卡留存功能规划

## Summary
基于测测/准准/好准竞品调研，规划"每日运势 + 日行一善打卡 + 订阅积分"留存变现体系。分三阶段：P0 订阅积分+AI对话扣费（变现地基）、P1 每日运势独立入口+日行一善打卡+福报值（日活抓手+差异化）、P2 改命可视化+本周运势日历+命格境界（深度留存）。本 plan 聚焦 P0+P1 实现细节，P2 概述。

---

## 一、竞品调研结论

| 维度 | 测测（心言集团） | 准准 | 好准 |
|---|---|---|---|
| 规模 | 6000万注册/日活100万/年营收数亿 | 千万级用户/4.8分 | 小（13评分） |
| 日活抓手 | **每日心情分+感情/财富/事业指标**（每天100万用户看） | 每日运势 | AI问答 |
| 变现 | **会员订阅为主**（几十万付费会员）+ 达人连麦按分钟（2.8-10.8元/分） | 真人连麦+问答 | 订阅99/月、199/季、599/年 + **单项解锁**（吉日吉时50.8/校准生辰72） |
| AI | 2019上线测测AI，心元大模型（网信办备案），AI情感陪伴/虚拟倾听师 | 问答 | 纯AI咨询 |
| 合规痛点 | 3·15被曝诱导高额消费（半年13万）/达人资质代考/涉封建迷信投诉800+ | 包装"泛心理" | — |

**五条启示**：
1. **每日运势是日活核心**（测测日活100万靠它）→ 你方向对，必须做到流日级才有日新鲜感
2. **变现地基=订阅+积分**（好准99/月599/年 + 单项解锁）→ 你已有 points/transaction/支付，地基在
3. **AI对话是留存第二曲线**（测测经验），且天然吃积分 → "订阅送额度→对话消耗→不够再买"闭环
4. **差异化机会**：了凡四训功过格（主动行善改命），竞品全是被动看运势，没人做行为闭环
5. **合规**：包装"传统命理文化+自我成长"，避免测测的迷信投诉

**关于"福报分动力不足"的解法**：不裸攒分，把福报值绑成 **改命进度**（对比先天命盘预期，了凡"命由我作"具象化）+ **即时命理反馈**（打卡回一句善行对日主五行的意义）。分有了出口和体感，才有动力。

## 三、Proposed Changes

### P0：订阅积分 + AI对话扣费（变现地基）

**目标**：会员订阅 + 积分消耗规则 + AI对话扣分/会员免费额度，跑通"订阅送额度→对话消耗→不够再买"闭环。

1. **新建 Subscription 模型** `backend/app/models/subscription.py`
   - 字段：user_id, plan(month/quarter/year), start_at, end_at, status(active/expired), auto_renew
   - 迁移：alembic 新增表

2. **会员权益与积分规则** `backend/app/config.py` 加配置
   - `MEMBER_DAILY_CHAT_QUOTA`（会员每日免费对话次数，如 10 次）
   - `NON_MEMBER_CHAT_POINTS_COST`（非会员每次 AI 对话扣分，如 20 分）
   - `MEMBER_DAILY_FORTUNE_UNLOCKED`（会员每日运势免费看）

3. **AI对话扣费逻辑** [chat.py](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/api/chat.py) `_generate_and_save` 前
   - 判断会员状态：active 且在期内 → 走免费额度（每日计数，超额度按非会员扣分）
   - 非会员/超额度 → 检查 points ≥ 扣分值，扣 points + 写 transaction（biz_type=daily_chat/followup）
   - 积分不足 → 返回 402 提示"积分不足，订阅会员或充值"

4. **订阅支付** 复用 [payment_service.py](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/services/payment_service.py) + order
   - 新增订阅商品 SKU（月/季/年），支付成功回调写 subscription 记录 + 续期

5. **前端**：我的页加"会员中心"入口 + 订阅卡片 + 积分余额/流水

### P1：每日运势独立入口 + 日行一善打卡 + 福报值（日活抓手+差异化）

**目标**：每日运势独立页面（日级流日+今日宜忌+压力+行动建议）+ 日行一善打卡闭环 + 福报值累积。

1. **流日算法** 新建 `backend/app/skills/divination/liuri_skill.py`
   - 参考 [analyze_liuyue](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/skills/divination/dayun_liunian_skill.py#L1101) 结构，算**日干支**（用 lunar 库或五鼠遁）+ 与原局/大运/流月的用忌神冲合关系 → 输出当日吉凶等级、宜忌方向、十神提示
   - 输出结构：`{ date, day_ganzhe, auspicious_level, yi:[], ji:[], pressure_level, shishen_hint }`

2. **每日运势生成** 新建 `backend/app/services/daily_fortune_service.py`
   - 组合 流日 + 当月流月 + 当前大运 → 调 LLM 生成短文本（< 300 字）：今日宜忌 + 近期压力点 + 今日行动建议（日行一善型，如"今天建议忍住一次反驳"）
   - 轻量 prompt，不复用重型 followup_structured；请求时实时算（无需定时任务）
   - 返回结构化 JSON + 缓存当日结果（Redis 或 DB，按 user_id+date 去重，避免重复调 LLM）

3. **日行一善打卡** 新建 `backend/app/models/daily_task.py`
   - 字段：user_id, date, action_suggested, action_done(bool), fortune_delta, reflected_text(可选), created_at
   - 新建 `backend/app/api/daily.py`：`GET /daily/fortune`（取今日运势+行动建议）、`POST /daily/checkin`（打卡，加福报值，返回即时命理反馈）

4. **福报值** [user.py](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/models/user.py) 加 `fortune_balance` 字段
   - 打卡 +N（参考功过格：善行分级，忍住反驳+3，日行一善+5，随喜+1 等）
   - 即时反馈：打卡后调 LLM 生成一句"该善行如何作用于你日主五行"（如"辛金日主，今日忍住反驳是金气收敛，养气之举，福报+3"）

5. **前端**：新增"今日"页（react-router 路由 `/daily`）
   - 运势卡片（宜忌/压力/吉凶等级）+ 行动建议卡 + 打卡按钮 + 福报值展示
   - recharts 画本周压力曲线（P2 扩展）

### P2：改命可视化 + 本周运势日历 + 命格境界（概述）

- **改命可视化**：福报值 → "改命进度条"，对比先天命盘流年凶吉预期，展示"你比先天命盘预期好了 X%"（了凡四训"命由我作"具象化，差异化核心）
- **本周运势日历**：流月+流日推 7 天，recharts 画压力/吉凶曲线
- **命格境界**：连续打卡天数 → 称号（修身/齐家/明德/至善），进阶成就感

## 四、Assumptions & Decisions

1. **MVP 优先级**：P0（订阅+对话扣费）先上，跑通变现地基；P1（每日运势+打卡）紧随，做日活。用户明确"核心订阅积分、AI对话能上"为 MVP。
2. **流日精度**：做到日（用户确认）。流日算法基于现有 analyze_liuyue 改，成本中等。
3. **福报分动力**：不裸攒分，绑"改命进度"+即时命理反馈（P2 改命可视化，P1 即时反馈）。用户反馈纯攒分动力不足，此为解法。
4. **每日运势无需定时任务**：流日干支实时可算，请求时生成 + 当日缓存。无 apscheduler 不阻塞。
5. **合规**：文案包装"传统命理文化/自我成长"，运势用"压力/宜忌/行动建议"而非"吉凶预测"绝对化措辞，规避测测式迷信投诉。
6. **差异化**：了凡四训功过格是竞品空白，作为长期核心叙事，但 P1 只做打卡+即时反馈，P2 做改命可视化完整闭环。

## 五、Verification

**P0 验证**：
- 非会员 AI 对话：points 扣减 + transaction 流水写入正确；积分不足返回 402
- 会员 AI 对话：每日额度内免费，超额扣分；订阅支付成功后 subscription 写入 + 权益生效
- 前端会员中心：订阅/积分/流水展示正确

**P1 验证**：
- 流日算法：对已知日期（如 2026-09-23）校验日干支正确性
- 每日运势：同 user 同 date 重复请求走缓存（不重复调 LLM）；内容含宜忌/压力/行动建议
- 打卡：福报值累加正确；即时反馈生成且关联日主五行；同日重复打卡不重复加分
- 前端今日页：运势/行动/打卡/福报值展示与交互正常

**P2 验证**（后续）：
- 改命进度条：福报值映射进度合理，对比先天命盘逻辑可解释
- 本周日历：7 天压力曲线数据连续，recharts 渲染正常
- 命格境界：连续打卡天数 → 称号进阶正确
