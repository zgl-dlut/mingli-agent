# 追问并发生成 + 中断重问修复方案

## Summary

解决两个问题：
1. **中断后无法重问**：旧 bug 切换人物中断生成后，`isGenerating` 卡住 → 输入框 `disabled` 不可用（"点不动"）；且中断时积分已扣、答案未存（孤儿问题），重问会再扣 40。
2. **A 生成时 B 也要能用**：当前 `isGenerating` 是全局单 bool，A 生成时所有人物输入禁用。改为按人独立的并发生成架构。

两个问题耦合：问题2的并发改造（输入始终可用 + 发送即取消该人物旧生成）直接解决"点不动"；问题1再叠加"重试未回答的上一条问题免扣费"保证公平。

## Proposed Changes

### A. 后端：重试未回答的上一条问题免扣费（问题1核心）

**文件**：[backend/app/api/chat.py](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/api/chat.py) `send_message`（L92-L189）

在 `deduct_points`（L117）之前插入判断：查询该 session 最新一条消息，若它是 user 消息且 content（trim 后）与本次相同（即重试被中断/未回答的上一问），则：
- 跳过 `deduct_points`（不重复扣费）
- 跳过 dedup 检查与 user 消息存盘（复用已有的孤儿消息）
- 直接进入 history 拉取 + stream_response（基于已有 user 消息重新生成 assistant）

```python
# 重试判定：上一条消息是相同内容的 user 消息（中断后重问），免重复扣费、不存重复 user 消息
last_msg_result = await db.execute(
    select(ChatMessage)
    .where(ChatMessage.session_id == session_id)
    .order_by(ChatMessage.created_at.desc())
    .limit(1)
)
last_msg = last_msg_result.scalar_one_or_none()
is_retry_unanswered = (
    last_msg is not None
    and last_msg.role == "user"
    and (last_msg.content or "").strip() == (request.content or "").strip()
)

if not is_retry_unanswered:
    await deduct_points(db, current_user.id, settings.POINTS_FOLLOW_UP, f"追问: {request.content[:30]}...")
    # 原 dedup 检查 + 存 user 消息逻辑保持不变（L122-L141）
# else: 重试，不扣费、不存重复 user 消息，直接用已有消息生成
```

**效果**：用户重问被中断的同一问题 → 免费、不产生重复 user 消息、重新生成 assistant。新问题照常扣费。

## Assumptions & Decisions

1. **并发模型**：不同人物可并发生成（A、B 同时跑各自 SSE）；同一人物发送新问题会取消该人物旧生成（用 genCounterRef 防止旧 finally 误清状态）。
2. **输入始终可用**：移除 `disabled={isGenerating}`，用户随时可打字、可发送。发送即取消该人旧生成。
3. **重试免扣费判定**：以 session 最新一条消息是否为相同 content 的 user 消息为准（即上一问未得到 assistant 回答）。后端 + 前端各做一次判定（后端权威，前端用于跳过积分门槛与按钮显示）。
4. **不退款历史已扣**：用户本次中断已扣的 40 不主动退款（无退款机制）；通过"重试免扣费"让用户不花第二次钱拿到答案，净付 40 得 1 答，公平。
5. **qwen 并发风险**：A、B 并发会同时向阿里云百炼发起 2 个请求，可能触发限流/配额不足（之前出现过 403 insufficient_quota）。属容量风险，非隔离 bug；并发失败时该人物的生成会走异常路径（finally 释放状态），不影响他人。
6. **currentMessage 保持全局**：不渲染（仅进度条 + 最终 fetchMessages），并发时滚动 effect 有轻微跨人触发，可接受，不改造为按人。
7. **不引入取消按钮**：输入始终可用 + 发送即取消旧生成，已覆盖"卡住后想重发"场景，无需额外按钮。
