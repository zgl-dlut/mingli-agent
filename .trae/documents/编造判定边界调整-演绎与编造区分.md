# 编造判定边界调整：区分"现实演绎"与"真编造"

## 背景
用户重新定义编造边界：**根据命盘信息做现实演绎不算编造；编造是指无任何命盘依据，或内容与命盘完全不一致**。

当前问题：评测端编造检测 prompt（`llm_scorer.py` L148-161）总纲"是否编造了命盘未提供的信息"过宽，把生成端允许的现实演绎（劫财助力→同辈帮忙、火土帮身→实业、话语权/中小团队等团队画像、调薪通道/谈判筹码等职场策略）也判成编造。实测 108 报告 17 条 high 编造几乎全是演绎类，属系统性误判。

## 用户确认的边界
- **团队/公司画像**（话语权/中小团队/成长型企业/扁平化管理）：分情况——有命盘依据链（喜用神→行业、身强→话语权）算演绎，纯凑话无依据算编造。代码层无法判依据链，交评测 LLM 按 prompt 判。
- **薪资/职场策略**（调薪通道/性价比/谈判筹码/薪资满意）：算演绎不抓（吉月帮身可推谈判优势/薪资趋势）。只抓具体数字（1.3倍/30%/B轮）。

## 改动清单

### 改动1：重写评测端编造检测 prompt（核心）
**文件**：`backend/app/services/eval/llm_scorer.py` L148-161
**原因**：当前 prompt 总纲过宽，把演绎也判编造，是 108 系17条误判的根源。
**改法**：把 prompt 的"检查标准"部分重写，明确三类算编造 + 一类不算编造（演绎），并给正反例。新 prompt 要点：
- 【算编造】①命盘数据编造（大运/流年/十神/用神忌神无中生有或写错，如戊申写成乙卯）②与命盘完全矛盾（凶月说吉、12月大凶说成"最稳妥入职月"）③无任何命盘依据的具体数字/事件（薪资倍数1.3倍、融资B轮、涨幅30%、具体日期几号入职、具体人物故事"表哥借钱"）
- 【不算编造·合理演绎】基于命盘吉凶/十神/五行做的现实场景化演绎：劫财→同辈助力、火土帮身→实业收益、冲主变动→换组换领导、吉月帮身→谈判筹码充足/薪资趋势向好、喜用神→行业方向（内容/教育）。给正例。
- 【团队画像分情况】话语权/中小团队/成长型企业：检查该画像前后文有无命盘依据链（如"火土帮身利实业→务实型成长企业"有依据链不算编造；"话语权大"前文有身强/比劫依据不算编造；纯孤立无依据才算 medium 编造）
- 严重程度：命盘数据编造/与命盘矛盾=high；无依据数字事件=high；纯凑话团队画像=medium
- 保留输出 JSON 格式 `{"编造": true/false, "编造内容": [...], "严重程度": "high/medium/low"}`

### 改动2：代码层移除团队画像关键词
**文件**：`backend/app/services/followup_structured.py` `_detect_fabricated_life_details`（L1606-1620 patterns 列表）
**原因**：用户定"团队画像分情况"，代码层无法判依据链（要看前后文有无命盘依据），硬抓会误伤有依据链的演绎。移除交给评测 LLM。
**改法**：从 patterns 移除这一行：
`(r'(?:扁平化管理|扁平化团队|话语权|中小团队|小型团队|中型团队|大厂螺丝钉|成长型团队|创业团队|管理风格|汇报扁平)', "公司规模/管理风格画像")`
保留：薪资倍数、融资轮次、涨幅百分比、offer集中、转化率/通过率、匹配度、成功率（这些是纯数字/量化指标，无依据，代码能确定判）。

### 改动3：生成端 prompt 补一句鼓励演绎（可选，防报告干瘪）
**文件**：`backend/app/services/followup_structured.py` L262-265 附近
**原因**：评测放宽后，生成端若仍过度保守会出干瘪报告。现有 L262-265 已允许演绎，补一句明确鼓励，让 AI 敢做现实场景化演绎。
**改法**：在 L265 后加一条：`允许并鼓励基于命盘吉凶/十神/五行做现实场景化演绎（如劫财→同辈助力、火土帮身→实业收益、冲主变动→换组换领导、吉月→谈判优势），这类演绎不算编造；只有命盘数据写错、与命盘矛盾、或凭空捏造具体数字/事件才算编造`

### 改动4：递增版本 + 单测 + 部署 + 提交
