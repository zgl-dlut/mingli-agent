# 加黑格式与小白友好度优化

## Summary

两个问题：
1. **加黑格式**：报告中"用忌指引：寻火取暖，培土筑堤"只有"用忌指引："被加黑，"寻火取暖"和"培土筑堤"未加黑。需在 prompt 中增加指引性短语的加粗指令。
2. **小白友好度**：首次报告过于专业，需增加小白能看懂的内容和更多通俗比喻。

## Current State Analysis

### 加黑格式现状

**前端** `reportFormat.ts`：
- 正则 `([KW_CHARS KW_PUNCT]+?)[：:]` 只匹配"关键词："格式
- `用忌指引：` 会被自动加黑为 `**用忌指引：**`
- `寻火取暖`、`培土筑堤` 不是"关键词："格式，不会被自动加黑

**后端** `prompt_builder.py:233`：
```
- 用神与忌神：明确标注**用神**（{yongshen}）和**忌神**（{jishen}），说明它们代表的方向。
```
- 只要求加粗"用神"和"忌神"两个词
- 未要求加粗指引性短语（如"寻火取暖，培土筑堤"）

### 小白友好度现状

**后端** `prompt_builder.py:262-274` 已有"小白友好·强制核心新规"：
1. 全程结论前置
2. 所有术语100%人话翻译
3. 去冗余、去科普、去模板化
4. 痛点+优势双向兼顾
5. 所有推演落地现实化
6. 排版轻量化
7. 结合现实年龄

但 LLM 输出仍偏专业，术语解释不够通俗。

## Proposed Changes

### 修改1：加黑指引性短语

**文件**：`backend/app/services/prompt_builder.py`
**位置**：第233行
**修改内容**：

将：
```
- 用神与忌神：明确标注**用神**（{yongshen}）和**忌神**（{jishen}），说明它们代表的方向。
```

改为：
```
- 用神与忌神：明确标注**用神**（{yongshen}）和**忌神**（{jishen}），说明它们代表的方向。用一句话给出"用忌指引"（如**寻火取暖**、**培土筑堤**），指引性短语必须用**加粗**包裹。
```

**为什么**：通过 prompt 指令让 LLM 主动加粗指引性短语，前端 ReactMarkdown 会正确渲染 `**短语**` 为加粗。不增加前端正则规则，保持代码健壮性。

**健壮性保障**：
- 前端 `reportFormat.ts` **不修改**，不增加新的正则规则
- 前端已有逻辑：`**短语**` 会被 ReactMarkdown 正确渲染为加粗
- 前端已有逻辑：`关键词：` 格式会被自动加黑
- 如果 LLM 未遵循加粗指令，前端不会误加粗（保持现有行为，不影响阅读）

### 修改2：增强小白友好度

**文件**：`backend/app/services/prompt_builder.py`
**位置**：第262-274行"小白友好·强制核心新规"
**修改内容**：

在第2条"所有术语100%人话翻译"后增加更具体的要求：

将：
```
2. **所有术语100%人话翻译**：出现食神、七杀、印星、身弱、自刑、食伤生财等专业词汇，必须同步搭配现实通俗解释，禁止纯术语堆砌，零阅读门槛。例：食伤生财=靠个人能力、业绩、技能赚钱；自刑=内心纠结、流程波折、事情反复内耗。
```

改为：
```
2. **所有术语100%人话翻译**：出现食神、七杀、印星、身弱、自刑、食伤生财等专业词汇，必须同步搭配现实通俗解释，禁止纯术语堆砌，零阅读门槛。例：食伤生财=靠个人能力、业绩、技能赚钱；自刑=内心纠结、流程波折、事情反复内耗。**每个命理术语首次出现时，必须紧跟括号解释**，如"七杀（一种带压力的克制力量）"。**每个章节至少包含1个生活化比喻**，用日常场景类比命理概念，如把"身弱财旺"比作"面前有座金山但只有小推车"。
```

**为什么**：用户反馈报告偏专业，需要更具体的小白化指令。增加"括号解释"和"生活化比喻"的强制要求，让 LLM 输出更通俗。

## Assumptions & Decisions

1. **不修改前端 `reportFormat.ts`**：加黑通过 prompt 指令控制 LLM 输出 `**短语**`，前端 ReactMarkdown 自动渲染。避免增加脆弱的正则规则。
2. **不修改前端渲染逻辑**：`whitespace-pre-wrap` 和 ReactMarkdown 配置保持不变。
3. **只修改后端 prompt**：所有调整集中在 `prompt_builder.py` 一个文件，便于回滚。
4. **试验性调整**：用户说"先调整一版，看下是否保留"，修改保持轻量，不过度重构。

## Verification Steps

1. **修改后重启后端**：uvicorn `--reload` 会自动重载
2. **创建新 person 测试**：创建新 person 触发首次解读，检查报告中：
   - "用忌指引"部分的指引性短语是否加粗（如 **寻火取暖**、**培土筑堤**）
   - 命理术语是否有括号解释
   - 每个章节是否有生活化比喻
3. **前端展示验证**：在 Chat 页面查看报告，确认加粗和排版效果
4. **健壮性验证**：如果 LLM 未加粗指引性短语，确认前端不会误加粗或报错
