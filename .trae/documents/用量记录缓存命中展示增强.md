# 用量记录缓存命中展示增强

## 摘要

在后台用量记录页面增加"是否命中缓存"直观指示列，让管理员一眼看出哪些请求命中了上下文缓存，以及缓存命中率。

## 现状分析

经过探索发现，**cached_tokens 字段已全链路实现**：

1. **数据库模型** [usage_log.py:26](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/models/usage_log.py#L26)：`cached_tokens` 字段已存在
2. **AI 服务** [ai_service.py:428-454](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/services/ai_service.py#L428-L454)：已从 response.usage 提取 `cached_tokens`（兼容 OpenAI `prompt_tokens_details.cached_tokens` 和 DashScope 原生 `cached_tokens`），并填充到 `usage_holder`
3. **落库逻辑** [chat.py:284](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/api/chat.py#L284)：`_record_usage_log` 已写入 `cached_tokens`
4. **Admin API** [admin.py:66](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/api/admin.py#L66)：已返回 `cached_tokens` 字段
5. **前端表格** [UsageDashboard.tsx:146](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/frontend/src/pages/UsageDashboard.tsx#L146)：已有"缓存token"列

**结论**：无需数据库迁移、无需后端改动。只需前端增强展示，增加"是否命中缓存"指示列和缓存命中率。

## 改动方案

### 文件：[UsageDashboard.tsx](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/frontend/src/pages/UsageDashboard.tsx)

**改动1：表头新增"命中缓存"列**（在"缓存token"列前插入）

在"总token"列后、"缓存token"列前，新增一列"命中缓存"，用于显示是/否徽章。

**改动2：表体新增"命中缓存"单元格**

根据 `r.cached_tokens > 0` 显示：
- 命中（cached_tokens > 0）：绿色徽章"是" + 缓存率（如 `42%`）
- 未命中（cached_tokens = 0）：灰色徽章"否"

缓存率计算：`cached_tokens / input_tokens * 100%`（input_tokens 为 0 时不显示率）。

**改动3：优化"缓存token"列显示**

当 cached_tokens > 0 时，用稍深色高亮显示数字，让命中缓存的行更醒目。

## 不需要改动

- ❌ 数据库迁移（cached_tokens 字段已存在）
- ❌ 后端模型（AiUsageLog 已有 cached_tokens）
- ❌ 后端 API（admin.py 已返回 cached_tokens）
- ❌ AI 服务（ai_service.py 已提取 cached_tokens）

## 验证步骤

1. `cd mingli-agent/frontend && npm run build` 确认构建通过
2. 重启前端 dev server
3. 重启后端 uvicorn
4. 访问 http://localhost:3000/admin/usage，确认新增"命中缓存"列正常显示
5. 检查有 cached_tokens > 0 的记录显示绿色"是"徽章 + 缓存率
6. 检查 cached_tokens = 0 的记录显示灰色"否"徽章

## 假设与决策

- **不新增 cached_chars 字段**：API 不返回缓存字符数，只返回缓存 token 数。字数（input_chars）记录的是完整输入长度，无法拆分缓存部分。因此只展示 token 维度的缓存命中。
- **不修改后端**：后端全链路已支持 cached_tokens，无需改动。
- **"是否命中"判定标准**：cached_tokens > 0 即为命中。
