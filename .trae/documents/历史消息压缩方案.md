# 历史消息压缩方案：结构化摘要保证前后一致性 + 长线剧情连贯

## 问题背景

当前 history 把该 session 下所有消息（含完整 JSON 报告）原样塞给 LLM，导致：
1. 上下文超 qwen-max 的 30720 tokens 限制
2. 重复问答堆积让 LLM 输出雷同（一直重复"你怕的被动裁员"开头）
3. **没有利用历史信息保证前后一致性**：prompt 里完全没有"参考之前结论保持一致"的要求

用户诉求：history 应"压缩"成有意义的摘要，用于保证：
- 前后回答一致性（不能这次说11月离职，下次说12月离职）
- 长线剧情连贯性（上次说入职新公司，下次追问副业能接上）
- 参考用户历史顾虑（用户一直担心裁员赔偿，新回答要呼应）

## 现状分析

### 报告结构（天然摘要源）
追问报告是结构化 JSON（`report_schema.py`），关键字段：
- `opening.verdict`：核心结论一句话（最关键）
- `subtopics[].title`：每个子问题的结论标题
- `summary.items[]`：行动清单（keyword + text）
- `summary.narrative`：总结叙事（与 items 二选一）

一份 1700-2500 字的完整报告，提取以上字段后摘要约 200-400 字，信息保留率足够支撑一致性。

### prompt 现状
`build_structured_prompt`（followup_structured.py 第27行）返回的 system_prompt 里：
- 有命盘数据（四柱、用神、大运、流年——固定的，每次都在）
- 有用户问题
- **没有历史摘要区块**
- **没有一致性要求**

### messages 构建
第549-567行，`messages = truncated_history + [当前问题]`，history 作为 OpenAI messages 数组传给 LLM。

## 方案：结构化提取摘要 + 注入 prompt + 一致性要求

### 决策理由
- 报告是 JSON，直接解析提取字段即可，**不需要额外调 LLM 压缩**（成本低、速度快、确定性高）
- 摘要注入 system_prompt，让 LLM 明确知道之前给了什么结论，并要求保持一致
- 不再传完整 history 到 messages 数组，避免超限和输出雷同

#### 1. 新增 `_build_history_summary()` 函数
从 history 里的 assistant 消息（JSON 字符串）提取关键结论：

```python
def _build_history_summary(history: list) -> str:
    """从历史 assistant 消息提取关键结论，构建历史摘要文本。
    
    每份历史报告提取：
    - opening.verdict（核心结论）
    - subtopics[].title（各子问题结论标题）
    - summary.items 或 summary.narrative（行动清单/总结）
    
    返回摘要文本，约200-400字/份。提取失败的历史消息跳过。
    """
    summaries = []
    for i, msg in enumerate(history):
        if msg.get("role") != "assistant":
            continue
        content = msg.get("content") or ""
        try:
            data = json.loads(content)
        except (json.JSONDecodeError, TypeError):
            continue  # 非 JSON（首次报告是 Markdown），跳过
        
        parts = []
        # 提取核心结论
        opening = data.get("opening") or {}
        verdict = opening.get("verdict")
        if verdict:
            parts.append(f"核心结论：{verdict}")
        
        # 提取各子问题结论标题
        subtopics = data.get("subtopics") or []
        titles = [st.get("title", "") for st in subtopics if st.get("title")]
        if titles:
            parts.append("已回答：" + "；".join(titles))
        
        # 提取行动清单
        summary = data.get("summary") or {}
        items = summary.get("items") or []
        if items:
            item_texts = [f"{it.get('keyword','')}({it.get('text','')[:40]})" for it in items[:5]]
            parts.append("行动建议：" + "；".join(item_texts))
        elif summary.get("narrative"):
            parts.append(f"总结：{summary['narrative'][:80]}")
        
        if parts:
            summaries.append(f"第{i}轮回答：" + " | ".join(parts))
    
    if not summaries:
        return ""
    return "\n".join(summaries)
```

#### 2. `build_structured_prompt` 新增历史摘要区块 + 一致性要求
在 prompt 的"# 命盘数据"之后、"# 用户问题"之前插入：

```python
# 历史对话摘要（从历史回答提取的关键结论，保证前后一致 + 长线剧情连贯）
{history_summary_section}
```

其中 `history_summary_section` 动态构建：
- 有历史摘要时：
  ```
  # 历史对话摘要（你之前给出的关键结论，本次回答必须保持一致）
  第1轮回答：核心结论：26年9月返岗不换组... | 已回答：9月返岗岗位变动；2027裁员赔付时机；最佳离职规划 | 行动建议：11月7日后离场(11月中下旬入职新公司)...
  
  ## 一致性要求
  - 本次回答的时间节点、判断结论必须与历史摘要保持一致，禁止自相矛盾
  - 长线剧情延伸：如果用户追问的是之前话题的后续（如入职后的发展），要承接历史结论往下讲，不要推翻重写
  - 用户核心顾虑：从历史问题中识别用户最担心的事（如裁员赔偿、离职时机），本次回答要呼应这些顾虑
  ```
- 无历史摘要时：区块为空字符串（首次追问不显示该区块）

## 假设与决策
- **假设**：追问报告是结构化 JSON，可直接解析提取；首次报告是 Markdown 不提取（首次报告后通常不立即追问同一话题）
- **决策**：结构化提取而非 LLM 摘要——成本低、确定性高、无随机性
- **决策**：摘要注入 system_prompt 而非 messages 数组——LLM 对 system_prompt 里明确标注的"一致性要求"执行权重更高
- **风险**：历史报告 JSON 解析失败（格式异常）时跳过该条，不影响当前生成
