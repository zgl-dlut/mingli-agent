# 追问开篇叙事化修复计划

## Summary

用户反馈每个追问回答的开头都是"34岁正式XXX，面对XXX"的固定句式，期望改成叙事化、关联用户情感和困境、直击用户内心的开头，避免固定模板。

经探索确认：该句式**不是 prompt 直接写的**（grep 整个 backend 未命中"34岁/正式...面对"），而是 LLM 自主生成的。根因有三：
1. 5个模板的"开篇承接"提供了3条**固定示例句子**，LLM 强依赖示例、倾向照搬或微调
2. 输入数据 `{age}岁，{age_stage}` 被LLM 拿来造句"34岁正式步入中年..."
3. 每个模板末尾的"输出格式示例"开头也是固定句式，进一步强化
4. 虽写了"禁止使用固定模板格式"，但**没列具体禁止句式**，LLM 不知道边界

本计划仅修改 `skill_prompts.py` 一个文件，纯 prompt 文案调整，不动代码逻辑。

## Proposed Changes

**仅改 `skill_prompts.py` 一个文件**。改动分3项，针对5个模板统一处理。

### 改动1：将"开篇承接"的"示例风格"替换为"风格方向 + 禁止句式 + 年龄使用规则"

**位置**：5个模板的"开篇承接"部分（career 137-140 / wealth 288-291 / marriage 434-437 / health 583-585 / general 740-743）

**当前4个通用模板内容**（career/wealth/marriage/general 共用上述3条示例）：

**替换为**：
```
   - **风格方向**（每次从以下方向中选择一种，禁止重复使用同一种）：
     - 情感共鸣式：直接回应提问中透露的情绪（焦虑、期待、犹豫、不甘），让用户感觉"被看见了"
     - 痛点直击式：一针见血指出用户处境中最核心的矛盾或两难，不讲套话
     - 场景代入式：描述一个与问题相关的具象画面或生活切片，有画面感
     - 悬念判断式：先抛出一个反直觉的命理判断，引发好奇，再逐步展开
     - 故事引入式：用一个简短的比喻或意象开场，与命局特征自然衔接
   - **禁止句式**（以下模式严格禁止，违反即不合格）：
     - 禁止"XX岁正式/步入/进入XXX，面对XXX"句式（含"正式步入""正式进入"等搭配）
     - 禁止"这是一个极其现实且充满战略博弈的好问题"
     - 禁止"听到您对XXX的关注/期待/担忧，我非常理解"
     - 禁止"站在XXXX年X月的节点上"
     - 禁止以年龄数字作为开篇主语或第一句话的开头
   - **年龄信息使用规则**：`{age}岁`和`{age_stage}`仅供内部推演参考，**禁止出现在开篇承接中**，可在子问题内部需要时自然提及
```

**health 模板特殊处理**（579-585行）：除上述替换外，还需把581行的场景化指令
```
   - **场景化**：结合具体时间点（如"站在2026年7月28日这个关键节点"）和用户身体状况
```
改为与其他4个模板一致：
```
   - **场景化**：结合具体时间点和用户处境，但**禁止使用固定模板格式**（如"站在2026年X月的节点"、"正处于XX流年的盛夏"等）
```
同时给 health 补上"多样化风格"和"精简要求"两条（当前 health 缺这两条），与其他4个模板对齐。

### 改动2：更新每个模板"输出格式示例"的开头

**位置**：5个模板末尾的示例开头（career 193 / wealth 330 / marriage 476 / health 624 / general 782）

5个开头各不相同，对应5种风格方向，确保 LLM 看到的是叙事化、直击情感的范例：

- **career**（193）→ 痛点直击式：
  `三个问题串在一起，本质上是一个核心抉择：什么时候走、怎么走才不吃亏、走完之后下一步是什么。`
- **wealth**（330）→ 悬念判断式：
  `先泼一盆冷水：2028年确实是财运爆发期，但如果不调整赚钱方式，多赚的钱也会以你意想不到的方式流走。`
- **marriage**（476）→ 情感共鸣式：
  `你问的不是"什么时候能遇到"，而是"为什么总是遇不到对的"——这个问题的答案，藏在你的命局偏好里。`
- **health**（624）→ 场景代入式：
  `身体的信号从来不是孤立的——你的脾胃不适、睡眠波动，背后是同一股五行能量在作祟。`
- **general**（782）→ 故事引入式：
  `把未来十年铺开来看，你的命盘像一部三幕剧：第一幕蓄力，第二幕爆发，第三幕跃迁。`

### 改动3（无新增代码）

不抽共享常量（如 `OPENING_DIRECTIVE`），原因：
- 5个模板的"输出格式示例"开头各不相同，无法完全共享
- health 模板"情感连接"描述与其他略有差异
- 遵循最小改动原则，避免过度工程化
- FORMAT_DIRECTIVE 是纯排版规则（与内容无关），开篇承接涉及内容风格，性质不同

## Assumptions & Decisions

1. **只改 skill_prompts.py**：追问链路 = `build_skill_prompt` → `SKILL_PROMPTS` / `GENERAL_FOLLOWUP_PROMPT`，不涉及 `prompt_builder.py`（首次解读）和 `prompt_rules.json`（v2.0 格式，当前未在追问链路使用）
2. **不改 FORMAT_DIRECTIVE**：开篇承接属于内容层，不属于排版格式层
3. **5个模板统一改**：开篇承接的"风格方向+禁止句式+年龄规则"5个模板保持一致结构；"输出格式示例"开头5个各不相同
4. **不新增代码逻辑**：纯 prompt 文案修改，不动 `build_skill_prompt`（1118行）和 `_build_context_vars`、`_get_current_time_info` 等函数
5. **不删除年龄输入数据**：`{age}岁，{age_stage}` 保留在"固定输入条件"第7条（供内部推演），仅禁止它出现在开篇承接

## Verification

1. **静态检查**：确认5个模板的"开篇承接"已替换为风格方向，无残留固定示例句子
2. **运行验证**：发送一个事业类追问（如"什么时候适合跳槽"），确认开头不是"XX岁正式..."句式
3. **多样性验证**：连续发送不同类型追问（财运、婚姻、健康、通用），确认每个开头风格不同
4. **重复验证**：连续发送2个同类型追问，确认开头不雷同
5. **长度验证**：确认开头不超过2句话，直击用户问题
6. **年龄验证**：确认 `{age}` 信息不出现在开头段落（可在子问题内部出现）
7. **健康专项**：发送健康类追问，确认开头不再出现"站在...节点"
