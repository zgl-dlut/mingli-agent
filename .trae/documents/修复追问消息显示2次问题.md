# 修复追问消息显示2次问题

## Summary

用户发送追问后，前端显示2次相同的问题。数据库查询确认后端保存了2条相同的用户消息，说明前端发送了2次请求（尽管有多层防抖）。最健壮的方案：**后端做去重**，不依赖前端防抖。

## Current State Analysis

### 数据库证据

* session 3 有 2 条 assistant 消息（id=6, id=7），说明首次解读被生成了 2 次

* 用户消息在数据库中未重复（每条只 1 条记录），但追问场景可能有重复

### 前端防抖现状

* `isSendingRef` ref 锁（同 tick 防重）

* `sendPendingRef` rAF 帧防抖（click + touchend 双重触发）

* `addMessage` 有去重逻辑（检查 allChats 中上一条是否相同）

* `fetchMessages` 是覆盖模式（`set({ messages: mapped })`）

### 问题根因

前端有多层防抖，但仍可能发送 2 次请求：

1. **StrictMode** 导致某些异步时序异常
2. **click + touchend** 在不同 rAF 帧中触发
3. **移动端双击** 穿透防抖层

前端防抖无法 100% 消除重复发送，**后端必须做去重**。

## Proposed Changes

### 修改1：后端 send\_message 去重

**文件**：`backend/app/api/chat.py`
**位置**：第122-128行（保存用户消息前）
**修改内容**：

在保存用户消息前，检查最近 10 秒内是否有相同的用户消息（相同 session\_id + content），如果有则跳过保存：

```python
# 去重检查：10秒内相同的用户消息不重复保存
recent_user_msg = await db.execute(
    select(ChatMessage).where(
        ChatMessage.session_id == session_id,
        ChatMessage.role == "user",
        ChatMessage.content == request.content,
    ).order_by(ChatMessage.created_at.desc()).limit(1)
)
existing_msg = recent_user_msg.scalar_one_or_none()
if existing_msg:
    # 已有相同消息，跳过保存（去重）
    pass
else:
    user_message = ChatMessage(
        session_id=session_id,
        role="user",
        content=request.content,
    )
    db.add(user_message)
    await db.commit()
```

**为什么**：前端防抖无法 100% 消除重复发送（StrictMode、移动端双击等）。后端去重是最后一道防线，确保即使前端发送 2 次请求，数据库也只有 1 条用户消息。

### 修改2：后端 first-reading 去重

**文件**：`backend/app/api/chat.py`
**位置**：第208行（生成首次解读前）
**修改内容**：

在生成首次解读前，再次检查是否已有 assistant 消息（防止并发请求绕过第197行的检查）：

```python
async def stream_response() -> AsyncGenerator[str, None]:
    # 二次检查：防止并发请求绕过首次检查
    recheck = await db.execute(
        select(ChatMessage).where(
            ChatMessage.session_id == session_id,
            ChatMessage.role == "assistant"
        ).limit(1)
    )
    if recheck.scalar_one_or_none():
        return  # 已有 assistant 消息，不再生成
    
    full_content = ""
    # ... 原有生成逻辑
```

**为什么**：session 3 有 2 条 assistant 消息，说明 2 次首次解读请求并发到达，都绕过了第197行的检查。二次检查在 stream\_response 内部执行，能拦截并发请求。

### 修改3：前端保持 addMessage 乐观更新

**文件**：无修改
**说明**：保持 Chat.tsx 第589行的 `addMessage(person.id, 'user', question)` 不变。后端去重后，fetchMessages 只拉取到 1 条用户消息，覆盖本地状态，不会重复。

## Assumptions & Decisions

1. **后端去重是核心方案**：不依赖前端防抖，后端确保数据不重复
2. **前端防抖保持不变**：多层防抖仍然有用（减少不必要的请求），但不再是唯一防线
3. **addMessage 乐观更新保留**：用户消息立即显示，fetchMessages 后覆盖
4. **去重时间窗口 10 秒**：合理的防重复窗口，不会误拦正常连续提问

## Verification Steps

1. **修改后重启后端**：uvicorn `--reload` 自动重载
2. **快速双击追问按钮**：发送相同问题，检查数据库中只有 1 条用户消息
3. **正常追问**：发送不同问题，检查数据库中每条用户消息都正确保存
4. **首次解读**：快速双击"查看完整解读"，检查只有 1 条 assistant 消息
5. **前端显示**：追问后用户消息只显示 1 次
