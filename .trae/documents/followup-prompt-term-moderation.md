# 追问报告术语管控调整方案（大白话主干+括号术语标签）

## Summary

将追问报告 prompt 的术语策略从"零术语"调整为"大白话主干（90%+）+ 术语作括号标签点缀"。术语带出形式是**大白话现象在前，括号里只放术语名作"命理出处标签"**（如"外部压力较大（七杀）"），而非"术语+括号解释意思"（如"偏官（七杀，代表外部压力）"）。小白读主干就懂，括号术语是给懂行的人看的出处标签，不打断通顺。仅改 `followup_structured.py` 的 `build_structured_prompt` 函数。

## Current State Analysis

当前 prompt（followup_structured.py build_structured_prompt，L107-302）术语管控极严格，且术语带出方式是"术语+括号解释"：

1. **L142 JSON示例 narrative**："极少数必要命理名词只用括号附带通俗解释，自然融入语句"
2. **L210 术语密度**："一整段narrative最多允许出现1个命理词汇，紧跟着括号大白话释义"
3. **L167**："命理名词解释只能揉进句子当中"
4. **对照示例 L262-268**：错误写法1判"术语超标"，正确写法1标"术语清零"
5. **L200 未来剧本**："不加专业术语"
6. **L295 正确写法4**："零术语"
7. **L276 正确写法2**：已有"火护着你（外部压力转成资源支持）"——这是"大白话+括号解释"，接近但括号里是解释非术语

问题：术语清零导致报告缺乏命理依据点睛；且"术语+括号解释"形式（如"偏官（七杀，代表外部压力）"）让术语在前、小白需读括号才懂，仍有打断感。

## 用户期望的新形式

**大白话现象 + 括号术语标签**（术语在括号里作"命理出处"标签，不在括号里解释意思，因为主干已说清现象）：

| 旧形式（术语在前+括号解释） | 新形式（大白话在前+括号术语标签） |
|---|---|
| 偏官（七杀，代表外部压力） | 外部压力较大（七杀） |
| 你日主属火（代表表达传播） | 你表达欲强、适合做内容（日主丙火） |
| 命盘喜火土，适合内容行业 | 适合内容/教育行业（命盘喜火土） |
| 流年丙午（火助身，合作运旺） | 今年合作运旺、容易谈成资源（流年丙午） |

小白读主干"外部压力较大"就懂，括号"（七杀）"是给懂行的人看的命理出处，可跳过。

## Assumptions & Decisions

1. **术语带出形式**：统一为"大白话现象+括号术语标签"（如"外部压力较大（七杀）"），括号里只有术语名，不在括号里解释意思。理由：主干大白话已说清现象，括号术语是给懂行的人看的出处标签，小白可跳过，不打断通顺。

2. **大白话占比 90%+**：术语只作括号标签点缀，密度一段最多1-2个。绝大多数 narrative 以现实剧本为主。

3. **允许作括号标签的术语**：单个十神名、五行属性、日主干支、用神方向、流年干支——这些是简短命理出处，主干大白话已解释现象，括号补术语即可。

4. **仍禁止的术语**（即便作括号标签也不允许）：干支纪时写法（→公历）、作用关系堆砌（X相冲/X破印/杀印相生，这类术语链过于专业）、排盘术语裸用（月令/宫位/日支/原局）、玄学话术（火土余温）。这些对小白无意义或会误导。

5. **不修改首次报告 prompt**：用户明确说"追问报告"，首次报告（build_first_reading_structured_prompt）不在本次范围。

6. **不改后端校验/前端渲染**：纯 prompt 措辞调整，不涉及 schema、容错、渲染链路。
