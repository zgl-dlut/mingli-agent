# 追问命盘方向锁定设计

## Summary

同一命盘多次追问得出矛盾结论（如1990人物副业：一次说2026起色、一次说2028启动），让用户感觉算不准。根因不是历史摘要缺失，而是 **LLM 没有被硬约束"严格依据命盘推测"**：
1. "命盘权威""严禁编造命理依据"等规则写在 `history_section` 区块里，而该区块因 `history_summary=""`（line 716 强制传空）完全不注入 → 这些规则现在根本没生效
2. 无"流年吉凶方向锁定"：命盘已注入"2026大吉、2028大凶"，但 LLM 仍敢给凶年安排启动类行动，因为 prompt 没禁止

本方案从源头堵死"瞎推测"：**把命盘权威规则从 history_section 抽到主体 prompt（无论有无历史摘要都生效）+ 新增流年吉凶方向锁定硬约束**，让 LLM 必须按吉凶下结论。同时恢复历史摘要注入用于话题承接（结论仍以命盘为准）。不做事后矛盾检查——靠预防层从源头杜绝。

### 根因2：无流年吉凶方向锁定
`_format_key_liunian`（[skill_prompts.py:1038](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/services/skill_prompts.py#L1038)）已清晰呈现每年吉凶：

## Proposed Changes（集中在 followup_structured.py 一个文件）

### 改动1：命盘权威规则从 history_section 抽到主体 prompt
- **文件**：`app/services/followup_structured.py` 的 `build_structured_prompt` 函数（line 89-125）
- **改法**：在 `# 命盘数据` 区块之后、`{history_section}` 之前，新增独立的 `# 命盘权威与方向锁定` 区块，把原 history_section 里的"命盘数据是最高推演依据""严禁编造命理依据""narrative 只能引用命盘数据栏已有信息"等规则移到这里。该区块**不依赖 history_summary**，始终注入。
- **为什么**：用户明确"不管有没有历史摘要都应按命盘推测"。命盘权威是核心约束，不该和历史摘要绑定。

### 改动2：新增"流年吉凶方向锁定"硬约束
- **文件**：同上，并入改动1的新区块
- **内容**：
  ```
  - 流年吉凶方向锁定（硬约束，禁止违背）：
    - 吉年（吉/大吉）→ 才能说"适合启动/推进/起色/有转机/可行动"
    - 凶年（凶/大凶）→ 只能说"慎入/避开/不宜启动/防守为主/缓一缓"
    - 禁止给凶年安排任何启动类行动（启动副业、跳槽、投资、开业、表白等）
    - 禁止把吉年说成"不宜/慎入"
    - 具体月份建议必须基于流月吉凶数据，禁止自行推测月份
  ```
- **为什么**：这是堵死"瞎推测"的核心。命盘已给吉凶标签，方向锁定让 LLM 必须按标签下结论，无法给凶年安排启动行动。同一命盘固定吉凶 → 多次追问结论方向必然一致。

### 改动3：恢复历史摘要注入（话题承接，命盘权威覆盖）
- **文件**：`app/services/followup_structured.py` line 716
- **改法**：
  ```python
  # 改前：system_prompt = build_structured_prompt(context, history_summary="")
  # 改后：
  system_prompt = build_structured_prompt(context, history_summary=history_summary)
  ```
  删除"临时：不参考历史摘要"注释。
- **history_section 简化**：命盘权威规则已移到主体，history_section 只保留历史摘要内容 + "历史摘要仅供话题承接，结论以命盘为准，冲突时以命盘为准并说明"的简要说明（2-3句，不再重复主体已有的详细规则）。
- **为什么**：历史摘要让多轮追问话题连贯（用户问过副业，再问时承接）。用户Q2确认"命盘高于历史，以最新命盘为准"——历史只做承接，结论仍由命盘方向锁定决定。

### 改动4：恢复后清理过时排查日志措辞
- **文件**：`app/services/followup_structured.py` line 728
- **改法**：`logger.info("...历史摘要为空（首轮追问/历史均为Markdown首次报告被跳过）")` 改为 `logger.info("...历史摘要为空（首轮追问无历史）")`，因为首次报告已是 JSON，旧措辞过时。
- **为什么**：避免日志误导排查。首次报告存库是 JSON（ai_service.py:412 yield json.dumps），`_build_history_summary` 能解析，旧注释"历史均为Markdown"已不成立。

## Assumptions & Decisions（假设与决策）

1. **命盘权威 > 历史摘要**：用户明确"命盘结果高于历史结论，以最新命盘为准"。方案以命盘方向锁定为核心，历史摘要仅话题承接。
2. **不做事后矛盾检查**：用户Q2强调"不瞎推测"——靠改动1+2的预防层从源头杜绝，而非事后比对重试。预防层让 LLM 无法违背吉凶下结论，自然无需兜底检查。
3. **不动 temperature**：当前 0.3 有随机性，但根因是 prompt 约束缺失而非随机性。方向锁定后即使 temperature=0.3，结论方向也被吉凶标签锚定。降 temperature 可能损害叙事性（用户重视故事感）。
4. **不动架构**：只改 prompt 构建逻辑 + 1行代码恢复，不动数据流、不改 schema、不动前端。
5. **命盘数据可信**：上一轮已诊断确认排盘算法无 bug（十神/流月/节气全对），命盘吉凶数据可信，可作为方向锁定的硬锚点。
