# 进入对话页跳登录修复计划

## Summary

用户反馈"一进入对话页面，就弹出到登录页了"。

根因：前端 `userStore.ts` 硬编码 `MOCK_MODE = true`，登录时**不调后端**、本地伪造 `mock-token-<timestamp>` 存入 localStorage。进入对话页时 `chatApi.getSessions()` 把假 token 发给后端，后端 `get_current_user` 用 `jose.jwt.decode` 验证 JWT 失败 → 返回 401 → 前端 `client.ts` 响应拦截器捕获 401 → 清除 localStorage token + `window.location.href='/login'`，用户被弹回登录页。

修复：把前端 `MOCK_MODE` 改为 `false`，走真实后端登录。后端已具备完整支撑：`SMS_MOCK_MODE=true`（固定验证码 `111111`）+ 真实 JWT 签发/验证（`SECRET_KEY` 已在 .env 配置），接口路径前后端完全匹配。

## Proposed Changes

### 改动1：关闭前端 MOCK_MODE

**文件**：`mingli-agent/frontend/src/store/userStore.ts`

**位置**：第24行

**当前**：
```ts
// Mock 模式开关：后端未启动时自动降级为本地 mock
const MOCK_MODE = true
```

**改为**：
```ts
// Mock 模式开关：后端未启动时自动降级为本地 mock
const MOCK_MODE = false
```

**为什么**：
- 后端已运行（http://localhost:8000）且 chat.py 路由加了 `Depends(get_current_user)`，必须用真实 JWT
- 后端 `SMS_MOCK_MODE=true` 已支持开发登录（固定码 111111），前端走真实登录后能拿到合法 JWT
- 改后 `sendSmsCode`/`loginWithSms` 走 `authApi` 真实分支，逻辑已正确实现，无需改其他代码

**影响范围**：仅 `sendSmsCode`（33-48行）和 `loginWithSms`（50-99行）两个函数的分支选择，其余代码不变。

## Assumptions & Decisions

1. **只改一行**：`MOCK_MODE = true` → `false`。其余前端代码（authApi、userStore 真实分支、LoginPage）和全部后端代码均无需改动
2. **不改响应拦截器**：`client.ts` 的 401→跳登录 是合理的安全行为，根因是假 token，修了 token 就不会再 401。改拦截器反而会掩盖问题
3. **不改后端认证**：后端 `get_current_user` 的 JWT 验证是正确的，不应为假 token 开后门（反模式、不安全）
4. **已登录用户需重新登录一次**：旧 mock-token 失效后，下次请求 401 → 跳登录页 → 用 111111 重新登录即可拿到真实 JWT。这是一次性代价
5. **token 30分钟过期**（`.env:4` `ACCESS_TOKEN_EXPIRE_MINUTES=30`）：改后用户每30分钟需重新登录一次。对命理咨询场景（生成报告+阅读+追问可能超30分钟）偏短，但**不在本次 bug 范围**，作为注意事项提示用户，是否调整由用户决定

## Verification

1. **清旧登录态**：浏览器 localStorage 清除 `mingli_token`、`mingli_user`（或直接访问 /login）
2. **真实登录**：输入任意11位手机号 + 验证码 `111111` → 登录成功 → 检查 localStorage `mingli_token` 是 JWT 格式（`xxx.yyy.zzz` 三段式），不再是 `mock-token-xxx`
3. **进入对话页**：从首页进入 `/chat/:personId` → **不再跳登录页** → 控制台无 401 → sessions/messages 正常加载
4. **追问功能**：在对话页发送追问 → 不跳登录 → 正常流式返回
5. **首次解读**：点击"查看完整解读" → 不跳登录 → 正常生成
6. **回归**：登录、退出、重新登录流程正常

## 注意事项（非本次范围，供参考）

- **token 30分钟过期**：若用户反馈"用一会又跳登录"，可考虑把 `.env` 的 `ACCESS_TOKEN_EXPIRE_MINUTES` 调长（如 720=12小时，或 10080=7天），或前端在 token 快过期时静默刷新（需实现 refresh 逻辑）。当前先不处理
- **生产环境**：上线前需把后端 `SMS_MOCK_MODE` 改 `false`（接真实阿里云短信），前端 `MOCK_MODE` 保持 `false`
