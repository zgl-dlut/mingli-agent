## Proposed Changes

### 第一阶段：修复显式缓存（3 种方案依次测试）

修改 `build_cache_control_messages` 函数（[ai_service.py:40-78](file:///Users/zhangguangling/Downloads/命理推算/mingli-agent/backend/app/services/ai_service.py#L40)），依次测试以下 3 种方案，每种用测试脚本验证后再生效：

**方案A：两个 block 都加 cache_control**
```python
content_blocks = [
    {"type": "text", "text": fixed_part, "cache_control": {"type": "ephemeral"}},
    {"type": "text", "text": dynamic_part, "cache_control": {"type": "ephemeral"}},
]
```
理由：文档说"单次请求最多支持 4 个缓存标记"，也许两个标记能让系统分别缓存两段。

**方案B：拆成两个 system message，第一个用 content 数组 + cache_control**
```python
return [
    {"role": "system", "content": [
        {"type": "text", "text": fixed_part, "cache_control": {"type": "ephemeral"}}
    ]},
    {"role": "system", "content": dynamic_part},  # 字符串格式
] + user_messages
```
理由：单 block 显式缓存已验证可行，把固定段独立成一个 system message（单 block + cache_control），动态段作为第二个 system message。

**方案C：整体不拆分，整个 system_prompt 加 cache_control**
```python
content_blocks = [
    {"type": "text", "text": system_prompt, "cache_control": {"type": "ephemeral"}},
]
```
理由：最简单。虽然动态部分每次不同导致缓存不会命中，但可作为基线验证 cache_control 是否被接受。

### 第二阶段：转用隐式缓存（如果显式都失败）

修改 `build_cache_control_messages`：
```python
def build_cache_control_messages(system_prompt: str, user_messages: list) -> list:
    SPLIT_MARKER = "# 本次会话信息"
    split_idx = system_prompt.find(SPLIT_MARKER)
    if split_idx > 0:
        fixed_part = system_prompt[:split_idx].rstrip()
        dynamic_part = system_prompt[split_idx:]
        # 拆成两个 system message，移除 cache_control，靠隐式缓存匹配公共前缀
        return [
            {"role": "system", "content": fixed_part},
            {"role": "system", "content": dynamic_part},
        ] + user_messages
    return [{"role": "system", "content": system_prompt}] + user_messages
```

理由：隐式缓存默认开启、无需标记、自动识别公共前缀。两个 system message 中第一个（固定规则）每次相同，是天然的公共前缀。
