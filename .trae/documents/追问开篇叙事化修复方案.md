# 追问开篇叙事化修复方案

## Summary

用户反馈每个追问回答的开头都是"34岁正式XXX，面对XXX"的固定句式。根因在 `skill_prompts.py` 中 5 个 prompt 模板的"开篇承接"部分：提供了 3 条**固定示例句子**被 LLM 照搬，加上 `{age}岁` 输入数据被 LLM 用作开头主语。虽然 prompt 写了"多样化风格"，但固定示例的信号强度远超多样性指令。

## Current State Analysis

### 文件：`backend/app/services/skill_prompts.py`

5 个 prompt 模板（career / wealth / marriage / health / general）都有相同的"开篇承接"结构：

**问题1：3 条固定示例被照搬**
```
- **示例风格**：
  - "这是一个极其现实且充满战略博弈的好问题！..."
  - "听到您身体一直不太好，我非常理解您对健康的担忧。..."
  - "这是一个非常深度的'家庭双打'战略问题。..."
```
LLM 从这 3 条中选一条或微调，导致开头高度雷同。

**问题2：输出格式示例强化固定模式**
每个 prompt 末尾的"输出格式示例"也有固定开头：
- career: "这是一个极其现实且充满战略博弈的好问题！..."
- wealth: "听到您对财运的关注，我非常理解..."
- marriage: "听到您对感情的期待，我非常理解..."
- health: "听到您身体一直不太好，我非常理解..."
- general: "这是一个非常现实且充满战略博弈的好问题！..."

**问题3：年龄数据被用作开头主语**
输入条件中有 `{age}岁，{age_stage}`，LLM 直接拿来造句"34岁正式步入中年..."。

**问题4：缺少禁止句式清单**
虽然写了"禁止使用固定模板格式"，但没有列出具体禁止的句式，LLM 不知道哪些模式算"固定模板"。

## Proposed Changes

### 改动1：重写"开篇承接"的"示例风格" → 改为风格方向（非完整句子）

**文件**：`skill_prompts.py`，5 个 prompt 模板的"开篇承接"部分

**当前**（career / wealth / marriage / general 共用，health 略有不同）：
```
   - **示例风格**：
     - "这是一个极其现实且充满战略博弈的好问题！将'想去腾讯'的野心与'拿赔偿金'的目标放在2027年这个时间节点上，我们必须进行一次清醒的'沙盘推演'。"
     - "听到您身体一直不太好，我非常理解您对健康的担忧。在即将到来的2028年，您的身体将进入一个全新的阶段。"
     - "这是一个非常深度的'家庭双打'战略问题。在一段长久的婚姻中，夫妻双方的运势往往是彼此咬合、互相影响的齿轮。"
```

**改为**：
```
   - **风格方向**（每次从以下方向中选择一种，禁止重复使用同一种）：
     - 情感共鸣式：直接回应提问中透露的情绪（焦虑、期待、犹豫、不甘），让用户感觉"被看见了"
     - 痛点直击式：一针见血指出用户处境中最核心的矛盾或两难，不讲套话
     - 场景代入式：描述一个与问题相关的具象画面或生活切片，有画面感
     - 悬念判断式：先抛出一个反直觉的命理判断，引发好奇，再逐步展开
     - 故事引入式：用一个简短的比喻或意象开场，与命局特征自然衔接
   - **禁止句式**（以下模式严格禁止，违反即不合格）：
     - 禁止"XX岁正式/步入/进入XXX，面对XXX"句式
     - 禁止"这是一个极其现实且充满战略博弈的好问题"
     - 禁止"听到您对XXX的关注/期待/担忧，我非常理解"
     - 禁止"站在XXXX年X月的节点上"
     - 禁止以年龄数字作为开篇主语或第一句话的开头
   - **年龄信息使用规则**：`{age}岁`和`{age_stage}`仅供内部推演参考，**禁止出现在开篇承接中**，可在子问题内部需要时自然提及
```

### 改动2：更新每个 prompt 的"输出格式示例"开头

**文件**：`skill_prompts.py`，5 个 prompt 模板末尾的示例

将每个示例的开篇承接改为**不重复的、叙事化的、直击情感**的开头：

- **career**：改为痛点直击式，如"三个问题串在一起，本质上是一个核心抉择：什么时候走、怎么走才不吃亏、走完之后下一步是什么。"
- **wealth**：改为悬念判断式，如"先泼一盆冷水：2028年确实是财运爆发期，但如果不调整赚钱方式，多赚的钱也会以你意想不到的方式流走。"
- **marriage**：改为情感共鸣式，如"你问的不是'什么时候能遇到'，而是'为什么总是遇不到对的'——这个问题的答案，藏在你的命局偏好里。"
- **health**：改为场景代入式，如"身体的信号从来不是孤立的——你的脾胃不适、睡眠波动，背后是同一股五行能量在作祟。"
- **general**：改为故事引入式，如"把未来十年铺开来看，你的命盘像一部三幕剧：第一幕蓄力，第二幕爆发，第三幕跃迁。"

### 改动3：health prompt 的"场景化"指令同步修改

**文件**：`skill_prompts.py`，health 模板的"开篇承接"

health 模板当前有独特的"场景化"指令（其他模板已禁止）：
```
   - **场景化**：结合具体时间点（如"站在2026年7月28日这个关键节点"）和用户身体状况
```
需改为与其他模板一致的禁止版本。

## Assumptions & Decisions

1. **仅改 skill_prompts.py**：追问使用 `build_skill_prompt` → `SKILL_PROMPTS` / `GENERAL_FOLLOWUP_PROMPT`，不涉及 `prompt_builder.py`（首次解读）和 `prompt_rules.json`（v2.0 格式，当前未在追问链路使用）
2. **不改 FORMAT_DIRECTIVE**：开篇承接属于内容层，不属于排版格式层
3. **5 个模板统一改**：career / wealth / marriage / health / general 的"开篇承接"部分保持一致结构，但"输出格式示例"的开头各不相同
4. **不新增代码逻辑**：纯 prompt 文案修改，不改动 `build_skill_prompt` 函数和 `_build_context_vars` 函数

## Verification

1. 发送一个事业类追问（如"什么时候适合跳槽"），确认开头不是"XX岁正式..."句式
2. 发送不同类型的追问（财运、婚姻、健康），确认每个开头风格不同
3. 连续发送 2 个同类型追问，确认开头不雷同
4. 确认开头不超过 2 句话，直击用户问题
5. 确认 `{age}` 信息不出现在开头段落（可在子问题内部出现）
