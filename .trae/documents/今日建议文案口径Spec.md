## 一、定位

「今日建议」是基于**当日流日 + 当月流月 + 当前大运**推导的「今天可执行的一件小行动」。

- 不是运势预告，不是吉凶预测，不是心理测评
- 合规包装：**传统命理文化 + 自我成长**（吸收竞品「赛博算命」投诉教训）
- 差异化落点：命理依据可查（对应产品「不编造」卖点）

---

## 二、方案 B 口径（核心决策）

一句话原则：**审核端看到的是行动语言，用户端能看到命理依据。**

| 段 | 术语策略 | 示例 |
|---|---|---|
| 行动句 `action` | **零术语**，纯行动语言 | 今天建议忍住一次反驳。 |
| 依据句 `basis` | **白话**，能量/状态视角 | 今日能量主收敛，宜蓄力，适合把想说的话先沉一沉。 |
| 依据行 `chart_ref` | **术语**，由算法算好注入，小字展示 | 依据：辛金逢比肩日，气机内敛 |

三段的职责分工：

- `action` 承担审核端与用户第一眼的可读性——不含任何命理词汇
- `basis` 解释「为什么是这条建议」——白话，不暴露术语
- `chart_ref` 满足「依据可查」——术语仅在此行出现，且**必须与算法输出完全一致**

---

## 三、长度约束

| 字段 | 上限 | 说明 |
|---|---|---|
| `action` | ≤ 20 字 | 动词开头，一行，句号收尾 |
| `basis` | ≤ 30 字 | 一行，白话 |
| `chart_ref` | ≤ 20 字 | 一行，小字 |
| 主卡合计 | ≤ 60 字 | 不含标题 |
| 完整版（解锁后） | ≤ 300 字 | 动作拆解 + 时段提示 + 依据详解 |

超长时**删内容**，不缩小字号、不省略号截断。

---

## 四、输出字段（API 契约）

```json
{
  "date": "2026-10-14",
  "advice": {
    "action": "今天建议忍住一次反驳。",
    "basis": "今日能量主收敛，宜蓄力，适合把想说的话先沉一沉。",
    "chart_ref": "辛金逢比肩日，气机内敛"
  },
  "source": {
    "liuri_ganzhi": "辛丑",
    "liuyue_ganzhi": "戊戌",
    "dayun_ganzhi": "癸卯",
    "shishen_tian": "比肩",
    "shishen_di": "偏印"
  },
  "grade": "good",
  "yi": ["见贵", "谈事", "学习"],
  "ji": ["远行", "动土"],
  "pressure_level": 0
}
```

**硬约束**（与现有追问链路同一规则，见 `backend/app/services/followup_structured.py`）：

- 十神、用忌神、冲合**全部由算法算好后注入**，`source` 字段即权威基准
- prompt 内必须写明「必须严格引用本行给出的名称，**禁止自行推演十神**」
- `grade` 只允许 `good | neutral | caution` 三个英文 token，**禁止**「大吉 / 大凶」等绝对化等级词；中文展示由前端映射（吉 / 平 / 慎）
- **等级双层**：算法内部 `judge` 保留原有 5 档（大吉 / 吉 / 平 / 凶 / 大凶，`_compute_overall_judge` 产出，不改动校准逻辑），对外只暴露 `grade`。映射表：

  | 算法 `judge` | 对外 `grade` |
  |---|---|
  | 大吉 / 吉 | `good` |
  | 平 | `neutral` |
  | 凶 / 大凶 | `caution` |

## 五、词表

### 5.1 必须

1. 具体动作、动词开头、当天可完成
2. 正向或中性，不制造焦虑
3. 依据句白话优先；术语只允许出现在 `chart_ref`

### 5.2 禁用

| 类别 | 禁用词 / 表达 |
|---|---|
| 绝对化 | 一定、必然、必将、注定、绝对、肯定、100% |
| 预测性 | 会、将、预示、命中注定、迟早、注定要 |
| 灾祸类 | 大凶、破财、血光、犯小人、冲煞、灾、劫难、凶险、霉运 |
| 迷信服务 | 开运、转运、化解、消灾、法事、开光、改运饰品、招财符、辟邪 |
| 诱导消费 | 付费即可改运、充值才能化解、买会员避灾、不开通就错过 |
| 专业指令 | 医疗诊断/用药、具体投资标的、法律结论 |
| 数字预言 | 加薪30%、涨1.3倍、必得X万、几日几号 |
| 术语裸用 | 单独出现的「吉凶」「煞气」「命里注定」 |

### 5.3 慎用

| 词 | 规则 |
|---|---|
| 辛金、比肩、食伤生财、劫财… | 必须配白话，或仅出现在 `chart_ref` |
| good / neutral / caution | 可用；不得升级为「大吉 / 大凶」，中文仅在前端映射 |
| 冲、合、刑 | 可用，但须翻译（冲=变动，合=合作，刑=反复内耗） |

## 六、边界规则

| 场景 | 规则 |
|---|---|
| 未成年档案 | 不给婚姻/恋爱/性别类建议；沿用 `skill_prompts.py` 年龄段规则（0-12 / 13-17 禁成人话题） |
| 情绪低谷 | 卡内关闭解锁/付费入口；不建议强制性或消耗性行动 |
| 命中危机词 | **不生成建议、不扣费**，直接展示心理援助热线（12356） |
| 忌神日 | 不给启动类行动（与「流年吉凶方向锁定」同规则：吉凶方向锚定结论方向） |
| 线下延伸 | 禁真人咨询、法事、开运物等任何线下迷信延伸（微信审核红线） |
| 危机优先级 | 危机词拦截 > 情绪模式 > 命理建议，命中即短路 |

## 十、接口命名契约（通用规则，适用于本功能及后续所有新接口）

### 10.1 字段命名

- 传输层 JSON 字段**一律英文 snake_case**
- 中文键**只允许**存在于 `bazi_data` 数据块内部（历史遗留，被 prompt 模板 / 测试 / 线上已落库的 `bazi_data_json` 共同依赖）——**冻结，不重构，新接口不得新增任何中文键**
- 枚举值**一律英文小写 token**，中文只在前端做展示映射

### 10.2 类型与格式

| 类型 | 规则 |
|---|---|
| 数字 | JSON number（禁止 `"13.9"` 这类字符串数字） |
| 布尔 | `true` / `false`（禁止 `0` / `1` / `"是"` / `"否"`） |
| 日期 | `YYYY-MM-DD` |
| 时间 | `HH:MM` |
| 时间戳 | ISO8601 **带时区** |
| 可空字段 | 显式 `\| null`，前后端两侧声明必须一致 |

### 10.3 单一事实来源

- 后端响应模型 = 契约基准
- 前端 `src/api/*.ts` 镜像后端字段，**不另起字段名**
- 前端 `src/types/index.ts` **只做 re-export**，禁止重复声明字段
- 需要前端专属字段时，用显式 `fromApi()` 转换函数，禁止隐式手工映射

### 10.4 已完成的对齐（V1.0 基线）

| 问题 | 处理 |
|---|---|
| `PersonResponse.user_id` 后端不返回 | 已删 |

| `UserInfo.phone` 后端不返回 | 后端 `/user/profile` 已补返回 |
| `UserInfo.email` 未声明 | 已补 `string \| null` |

| `types/index.ts` 与 `api/*.ts` 双份发散定义 | 已收敛为 re-export |
